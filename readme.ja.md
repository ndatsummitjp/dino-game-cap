# はじめに

[English](./readme.md)

CAP プロジェクトへようこそ。

このプロジェクトには、推奨される構成に従って次のフォルダーとファイルが含まれています。

| フォルダーまたはファイル | 用途 |
|---|---|
| `app/` | UI フロントエンド |
| `db/` | ドメインモデルとデータ |
| `srv/` | サービスモデルとコード |
| `readme.md` | 英語版のスタートガイド |

## 次のステップ

- 新しいターミナルを開き、`cds watch` を実行します。
- VS Code では、**ターミナル** > **タスクの実行** > **cds watch** を選択することもできます。
- `db/` 内の CDS ファイルでドメインモデルを定義します。

CAP の TypeScript サービスを実行するには、Node.js 24 以降が必要です。

## UI のビルド

プロジェクトのルートで `npm run build:ui` を実行すると、UI5 アプリがビルドされます。ビルド成果物は `gen/srv/app/` に出力され、CAP から自動的に配信されます。

`npm run build:cds` を実行すると、本番用の CAP サービスがコンパイルされます。生成された Node.js サービスは `gen/srv/` に出力されます。

## Docker と PostgreSQL で実行する

`docker compose up --build`（または `npm run docker:up`）を実行して、本番用イメージをビルドし、PostgreSQL とともにアプリを起動します。CAP のランディングページは <http://localhost:4004>、ゲーム UI は <http://localhost:4004/game/> で開けます。Compose はローカル利用向けに CAP のサービス一覧を有効にし、モック認証を使用します。開発環境の外部に公開する前に、実際の認証を設定してください。

実行用イメージには、生成済みの `gen/srv` サービスと `gen/pg` データベース配置用成果物、および本番用依存関係のみが含まれます。ソースファイルとビルドツールはビルドステージに残ります。生成された PostgreSQL 配置処理は、サービスの起動前に実行されます。

Compose ファイルでは、ローカル開発用のデータベース名、ユーザー名、パスワードに `dino` を使用します。変更する場合は、`POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD` を環境変数で設定してください。データベースは `postgres-data` ボリュームに保存されます。データを保持したまま停止するには、`docker compose down`（または `npm run docker:down`）を実行します。

## キャラクター画像のアップロード

キャラクターのオブジェクトページで **画像をアップロード** を選択すると、複数の画像ファイルを選べます。ファイル名は、対象フィールド名 `idle_image`、`run_1_image`、`run_2_image`、`jump_image`、`crash_image` のいずれかに、`.png`、`.jpg`、`.jpeg`、`.gif`、`.webp` の拡張子を付けてください。たとえば `idle_image.png` は `idle_image` フィールドを更新します。フィールド名が不明なファイルは無視されますが、対応するファイル名が少なくとも 1 つ必要です。対応ファイルは 10 MiB 以下で、ファイルの内容が拡張子に一致している必要があります。ドラフト編集中にアップロードした画像はドラフトに保存され、ドラフトを有効化すると反映されます。

UI は選択したファイルをまとめて `/odata/v4/dino/uploadCharacterImages` の `images` パラメーターに送信します。各項目には、キャラクターの `id`、`IsActiveEntity` の状態、`fileName`、Base64 エンコードされた `content` が含まれます。同じキャラクターの同じ状態で同じフィールドを複数回更新するファイルは拒否されます。
